# SD-WAN 边缘转发与中心控制仿真系统

一套用 Go 实现的软件定义广域网（SD-WAN）仿真：包含边缘设备转发面、中心控制器、
随时间变化的多链路网络仿真和应用流量生成。用同一套边缘决策核心驱动两种引擎：

- **流体引擎（fluid）**：1 秒一个时间粒度，可跑几百门店 × 数天的验收对照；
- **包级引擎（packet）**：真实探测包、复制去重、迁移乱序，驱动实时仪表盘。

## 目录结构

```
internal/
  model/       领域类型：应用、链路、策略、遥测
  clock/       确定性虚拟时钟与定时器堆
  network/     时变链路模型（晚间宽带劣化、OU 噪声、排队、故障）、拓扑、包队列
  classify/    四层流量识别 + 流级缓存
  probe/       每条链路持续探测，EWMA 测量 RTT/丢包/抖动
  edge/        边缘引擎：评分选路、滞回迁移、乱序控制、双发去重、大流量限速
  controller/  中心控制器：策略版本化下发、全网遥测、失联自治、HTTP 传输
  sim/         流量生成、故障场景、流体/包级两套引擎、验收指标
  report/      Markdown + JSON 验收报告
  web/         实时仪表盘（内嵌静态页）与故障注入 API
cmd/sdwan/     命令行入口
```

## 快速开始

```bash
# 小规模冒烟（20 店 × 6 小时，秒级出结果）
go run ./cmd/sdwan quick

# 全量验收（300 店 × 3 天，全走专线 vs 按质量选路对照）
go run ./cmd/sdwan accept -stores 300 -days 3

# 实时仪表盘：http://localhost:8080
go run ./cmd/sdwan serve

# 从已有紧凑 JSON 重新生成 Markdown（改了报告文案后无需重跑仿真）
go run ./cmd/sdwan rerender -json output/acceptance.json -md output/acceptance.md
```

常用参数：`-stores`、`-days`/`-hours`、`-load`（流量倍率）、`-seed`（可复现）、
`-out`（报告目录）、`-workers`（并行 worker 数，0=按 CPU 核数，1=串行）、
`-cpuprofile`。

产物（写入 `-out` 目录）：

- `acceptance.md`：人类可读的对照验收报告；
- `acceptance.json`：紧凑聚合指标（逐流中断明细已聚合为计数/均值/最长）；
- `acceptance-series-baseline.json` / `acceptance-series-sdwan.json`：
  每分钟一个点的时间序列（三链路带宽 + 各应用 SLA），供画图与二次分析。

## 核心机制与需求对照

### 1. 应用识别（`internal/classify`）

按优先级分四层，识别结果按流缓存，直到流结束才释放：

1. **目的地址 + 端口规则**（CIDR 前缀 + 端口集合）；
2. **DNS 解析关联**：模拟 DNS 响应把域名解析出的 IP 绑定到应用；
3. **首包特征签名**：ISO8583、RTP、TLS SNI marker、rsync；
4. **行为归类兜底**：按平均包长、包间隔、累计字节区分大流量/周期小包/交易突发/通用。

识别依据（`port:`/`dns:`/`sig:`/`behavior:`/`pending`）会随每条流显示在仪表盘上，
验收用生成器真值统计分类准确率。

### 2. 链路探测（`internal/probe`）

每条链路每秒一个探测，维护：

- RTT、抖动的 EWMA；
- 30 个探测的滑动丢包窗口；
- 连续全丢/链路中断 → 标记不可用。

流体模式由链路模型做确定性伯努利试验；包级模式探测包真实进队列、走时延、等回包。
质量视图每个 tick 只采样一次并缓存，避免噪声被重复推进。

### 3. 选路、滞回迁移与乱序控制（`internal/edge`）

- 每条链路对每个应用算 0–100 分：RTT/丢包/抖动对 SLA 门限的归一化、利用率、
  费用、应用链路偏好；
- 新流按分择优；存量流重评估时带**滞回**：现链路仍达标且候选优势不超过
  `MigrateScoreMargin` 就不迁；现链路劣化必须持续满 `HoldDown`（默认 20s）才迁，
  杜绝来回切换；
- 非实时流迁移时在接收端开启 `ReorderWindow` 重排窗口，实时流（RTP）直接切；
- 关键应用（收银、会议）在所有链路都不满足 SLA、或首选链路处于临界质量时，
  启用**双链路复制发送**，接收端按流 + 序号滑动窗口去重。

### 4. 限速与成本（`internal/edge`）

- 大流量（备份/更新）走边缘全局令牌桶限速（默认 4 Mbps），且只能走便宜链路：
  宽带优先、移动网次之、专线仅在便宜链路全断时兜底；
- 移动网按 GB 计费，策略里配置 `cost_per_gb`，验收报告统计总费用。

### 5. 中心控制器与失联自治（`internal/controller`）

- 策略版本化下发；边缘周期性 pull 策略 + push 遥测；
- 控制器失联时边缘用本地缓存的**最后一份策略**继续转发，恢复后自动重新同步；
- 同时提供进程内客户端（仿真）和 HTTP 客户端/服务端（真实设备）。

## 仿真网络的真实性

- 每条链路有独立种子的均值回归（OU）噪声，RTT/丢包/抖动/带宽随时间变化；
- **宽带 19:00–24:00 晚高峰劣化**：RTT、抖动、丢包上升，容量下降；
- 专线营业时段有轻度拥塞基线，利用率越高排队时延和拥塞丢包越严重；
- 移动网卡晚高峰轻度劣化并按流量计费；
- 故障场景（`sim/faults.go`）：专线容量压缩、宽带中断/劣化、移动网故障、
  控制器失联，全部按确定性时间表注入与恢复。

## 验收指标

`accept` 同时跑两个模式（基线=全走专线，实验=按质量选路），输出对照：

1. 各应用质量达标率（SLA 采样：每流每秒）；
2. 专线/宽带/移动网带宽用量；
3. 移动网流量费用；
4. 关键应用中断窗口的平均与最长时长；
5. 流迁移次数、反复切换次数、复制 tick、识别准确率、限速字节、控制器自治时长。

报告写到 `output/acceptance.md` 与 `output/acceptance.json`。

## 测试

```bash
go test ./...           # 单元 + 仿真确定性/故障/识别/选路测试
go test -race ./...     # 数据竞争检测
go test ./internal/edge -bench=. -benchmem   # 边缘热路径基准
```

仿真结果对 worker 数量不敏感（串行与多并行结果逐字节一致，见
`TestDeterminismAcrossWorkerCounts`），同一种子可完整复现。
